# 2026-10-22：全局搜索覆盖与设置定位修复

## 范围和原因

用户反馈：全局搜索只能找到部分设置和一级菜单，大量二级菜单与设置无法检索。

本轮从实际 `desktop-preview/src/App.tsx` 启用的路由、设置页四个子菜单及现有控件出发核对。原 `config/search-index.ts` 只有 8 个页面条目；全局搜索只比较名称和少量关键词。它没有登记 FrameScope 的采样、自启动、日志、更新开关，以及大部分外观和 OSD 控件。

同时定位到三处相关跳转/交互问题：

- 设置页手动切换子菜单只更新本地 state，URL 仍指向旧子菜单，重复搜索相同地址时容易停在错误分组。
- 同名控件可能被定位到错误位置，例如主题自定义颜色与 MR 背景自定义颜色。
- 搜索结果依赖 startup context 的新建 `tools: []`，硬件刷新导致列表重建、键盘选中项重置；列表滚动到鼠标指针下方时，旧 `mouseenter` 处理又会覆盖键盘选择。

## 修复内容

1. 将索引补至 112 项：10 个页面/子菜单入口，以及 102 个具体功能或设置入口。覆盖通用、外观、FrameScope 采样与报告、关于/更新、悬浮监控、硬件操作、首页监控、目标管理及报告操作。
2. 搜索结果显示所属页面、子菜单和分组；条件项有说明，例如“仅竖排样式可用”“选择 MR 背景后可用”“选择报告并打开详情后可用”。
3. 使用索引中固定的页面及 `focus` 标识跳转，再滚动、聚焦并短暂标记对应设置。按分组限定查找范围，同名控件不跨组匹配。
4. 条件控件当前不可见时，定位到其拥有的设置分组，不开启液态玻璃、不更换背景/OSD 样式、不修改开关。
5. 设置页的当前子菜单直接由 URL 决定；手动菜单切换同步 URL 并移除旧 focus，不堆积子菜单历史。重复搜索、后退和前进都恢复到正确分组。
6. 支持前后空格、多个词、全角字母、中英文之间有无空格、当前语言标签和常用别名。例如 `GitHub加速`、`Windows启动`、`CPU 分核电压`、`竖排 透明度`、`ＰａｗｎＩＯ`。
7. 精确设置名称优先于泛页面关键词；键盘选中结果会在弹出列表内滚动。结果不再依赖硬件数据刷新，静止鼠标不会抢走键盘选中项。
8. 为搜索输入和结果补上 combobox/listbox/option 语义，Esc 关闭列表而不触发 OSD 页的全局返回。

搜索是导航，不执行结果所描述的动作：不会自动启动监控、删除目标/报告、安装驱动、下载更新或更改设置。报告操作仍需用户选择具体记录；未索引已移除的音乐、系统优化、第三方工具等旧 NexBox 路由。
